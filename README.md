# Yutverse Online

React + TypeScript + Vite / React Three Fiber 기반의 3D 증강 윷놀이입니다. 싱글플레이와 2~4인 온라인 개인전을 지원합니다.

## 실행

Node.js **24 이상**, npm을 사용합니다 (`.nvmrc`: 24). 현재 클라우드에서 Node 24.22.1 / npm 11.9.0으로 검증했습니다. 서버는 Node 내장 `node:sqlite`를 사용합니다.

```sh
npm ci
# 터미널 1: Express + Socket.IO + SQLite (3001)
npm run dev:server
# 터미널 2: Vite (5173), /api 및 /socket.io를 3001로 프록시
npm run dev
```

싱글플레이만 하려면 `npm run dev`만 실행한 뒤 `로그인 없이 싱글플레이`를 고르면 됩니다. 브라우저에서 파일 로드 후 서버 없이 규칙·AI·증강을 실행합니다. 오프라인 **새로 접속**을 위한 서비스 워커/PWA는 아직 없습니다.

```sh
npm test             # 공통 엔진 + 실제 소켓 + SQLite 통합 테스트
npm run build        # 서버 및 웹 TypeScript 검사 + 웹 프로덕션 빌드
npm start            # 3001에서 정적 웹 + API + Socket.IO를 함께 제공
npm run test:browser # 개발 서버 두 개 실행 후, 시스템 Chromium으로 브라우저 테스트
```

브라우저 테스트는 Playwright와 `/usr/bin/chromium`을 사용합니다. 다른 환경은 `CHROMIUM_PATH`로 Chromium 경로를 지정합니다. `YUTVERSE_URL`로 기본 테스트 주소를 바꿀 수 있습니다. 브라우저 테스트는 지정 서버에 테스트용 계정과 경기 전적을 생성하므로 테스트 전용 DB를 사용하세요. 스크린샷은 `/tmp/yutverse-browser`에 저장됩니다.

## 게임과 증강

- 싱글: 사람 1명 + AI 1~3명, 쉬움/보통/어려움. 윷 확률은 난이도와 관계없이 동일합니다.
- 온라인: 방 제목·인원·선택 비밀번호로 방 생성 → 방 목록에서 눌러 참가 → 전원 준비 → 방장이 시작합니다. 초대 코드 입장도 지원합니다. AI는 참가하지 않습니다.
- 플레이어당 말 4개. 도/개/걸/윷/모/빽도, 잡기, 업기, 지름길, 추가 던지기. 첫 완주 이후에도 남은 순위까지 진행합니다.
- 시작점에 정확히 도착하면 아직 완주가 아니며 한 칸 더 지나야 완주합니다. 지름길은 꼭짓점에서 이동을 시작할 때 진입합니다. 빽도는 해당 말의 이동 이력을 역으로 따라갑니다. 첫 두 모서리와 중앙에서 이동을 시작하면 사용할 길을 직접 고릅니다. 중앙을 지나치기만 할 때는 들어온 대각선 방향을 유지합니다.
- 추가 던지기를 먼저 마친 뒤 모아 둔 결과 중 사용할 것을 고릅니다. 결과 하나로 이동할 때마다 그 결과만 소모합니다. 윷/모와 잡기의 추가 던지기는 누적됩니다. 네 윷은 독립·공정한 확률입니다: 모 1/16, 빽도 1/16, 도 3/16, 개 6/16, 걸 4/16, 윷 1/16.
- 증강은 시작 전 전원에게 1개, 이후 **각자의 기본 턴** 2·4·6·8회 시작에 1개씩 받습니다. 추가 던지기는 기본 턴 횟수를 늘리지 않습니다.
- 보유하지 않은 적격 증강에서 중복 없는 후보 3개를 무작위로 제공합니다. 영웅 최대 1개, 슬롯 최대 5개. 소모한 일회용 카드도 슬롯에 남고 다시 뽑히지 않습니다.
- 선택 중 전체 게임의 윷·이동·수동 증강 사용이 정지됩니다. 60초 후 첫 후보를 자동 선택합니다. 시작 전에는 좌석 순서대로 선택합니다.
- 이동 보너스는 수동/자동을 합쳐 결과당 최대 **+2**입니다. 빽도에는 앞으로 가는 이동 보너스를 적용하지 않습니다. 증강이 추가하는 던지기는 대기 중 던지기가 4회 미만일 때만 지급하며, 일반 잡기로 얻은 던지기를 줄이지 않습니다.

| 증강 | 방식 | 효과 |
|---|---|---|
| 작은 발걸음 | 자동·지속 | 도 이동 +1 |
| 두 걸음의 여유 | 자동·지속 | 개 이동 +1 |
| 걸음의 리듬 | 자동·지속 | 걸 이동 +1 |
| 힘찬 출발 | 자동·지속 | 대기 말 출발 이동 +1 |
| 마지막 질주 | 자동·지속 | 외곽 16~19번에서 출발 이동 +1 |
| 함께 달리기 | 자동·지속 | 업은 말 이동 +1 |
| 추격자 | 자동·지속 | 잡기 추가 던지기 +1, 기본 턴당 1회 |
| 달빛 방패 | 자동·1회 | 한 무리의 잡기를 방어 |
| 다시 출발 | 자동·1회 | 잡힌 무리를 1번으로 복귀 |
| 완주의 선물 | 자동·1회 | 완주 시 추가 던지기 +1 |
| 다시 한 번 | 수동·1회 | 골라 둔 결과 재추첨. 이미 받은 추가 던지기는 유지 |
| 바람 한 줌 | 수동·1회 | 앞으로 가는 결과 이동 +1 |
| 도약 | 수동·1회 | 앞으로 가는 결과 이동 +2 |
| 뒤집힌 운명 | 수동·1회 | 빽도를 도로 변경 |
| 안정된 걸음 | 수동·1회 | 앞으로 가는 결과를 두 칸으로 변경, 원래 추가 던지기는 유지 |
| 비장의 한 수 | 수동·1회 | 던지기 대기 중 추가 던지기 +1 |
| 바람의 주인 | 영웅·자동 | 앞으로 가는 이동 +1 |
| 수호자의 맹세 | 영웅·자동·2회 | 잡기 방어 |
| 불사조 | 영웅·자동·1회 | 잡힌 무리를 5번으로 복귀 |
| 끝없는 여정 | 영웅·자동 | 완주 추가 던지기 +1, 기본 턴당 1회 |
| 두 번의 여유 | 수동·1회 | 던지기 전에 사용하면 2번 더 던지기 |
| 주머니 속 여분 윷 | 자동·1회 | 다음에 윷을 던진 뒤 1번 더 던지기 |
| 세 번째 차례의 선물 | 자동·지속 | 내 3·6·9번째 차례마다 1번 더 던지기 |
| 윷 보따리 | 영웅·수동·1회 | 던지기 전에 사용하면 최대 3번 더 던지기 |
| 도의 메아리 | 자동·지속 | 도가 나오면 1번 더 던지기, 내 차례마다 1회 |
| 모의 메아리 | 자동·지속 | 모가 나오면 원래 보상에 1번 더 던지기, 내 차례마다 1회 |

방패는 무리 전체를 한 번에 보호합니다. 막힌 경우 서로 다른 플레이어의 말이 같은 칸에 함께 있을 수 있으며 서로 업지는 않습니다. 달빛 방패/수호자의 맹세, 다시 출발/불사조는 동시에 보유할 수 없습니다. 대기 말만 있어 이동 불가인 빽도는 변환/재추첨 카드가 있으면 사용할 기회를 주고, 사용하지 않고 넘길 수도 있습니다.

## 온라인 동작과 저장

서버만 윷 결과·이동·증강 후보·효과·순위를 결정합니다. 클라이언트는 의도와 현재 방 revision을 보냅니다. 다른 차례의 행동, 불법 이동, 선택 중 행동, 소모한 카드 재사용, 오래된 revision 요청은 거부합니다. 온라인 난수는 Node `crypto.randomInt`를 사용합니다. 후보는 선택 중인 본인에게만 전송합니다.

아이디·비밀번호·닉네임으로 회원가입하고 로그인합니다. 아이디는 영문·숫자·밑줄 4~24자(대소문자 구분 없음), 닉네임은 1~16자, 비밀번호는 8~128자입니다. 비밀번호는 무작위 salt와 Node `scrypt`로 해시하며 평문으로 저장하지 않습니다. 무작위 256비트 로그인 토큰은 서버에 해시로만 보관합니다. 로그인 유지를 선택하면 localStorage에 보관하고 서버에서 30일 후 만료합니다. 선택하지 않으면 sessionStorage에 보관하고 서버 유효기간은 최대 12시간입니다. 로그아웃하면 해당 토큰과 소켓 연결을 해제합니다. 계정의 동시 온라인 접속은 마지막 소켓 연결만 유지합니다.

기존 게스트 토큰이 같은 브라우저에 남아 있으면 회원가입 시 그 사용자를 계정으로 전환해 기존 온라인 전적을 유지합니다. 다른 기기·다른 임시 공개 주소에서도 같은 서버의 계정으로 로그인하면 서버에 저장된 전적을 볼 수 있습니다. 아이디 찾기·비밀번호 재설정은 사전에 보관한 복구코드로 제공합니다. 기존 게스트 토큰을 잃어버린 상태의 복구는 제공하지 않습니다.

- 연결이 끊기면 90초 동안 좌석을 유지하며 이후 자동 기권합니다. 대기실에서는 유예 후 퇴장합니다.
- 온라인의 던지기/이동/사용 행동 대기 시간은 120초이며, 초과 시 자동 기권합니다. 증강 선택 시간은 별도 60초이고 턴 타이머는 정지합니다.
- 기권 순서대로 남은 순위의 아래쪽을 배정합니다. 한 명만 남으면 남은 플레이어를 포함해 순위를 확정합니다. 완주·기권한 플레이어는 이후 차례에서 제외합니다.
- 서버를 재시작해도 진행 상태·후보·증강 선택·세션·완료 전적을 SQLite에서 복구합니다. 재시작 시 접속 상태를 초기화하고 재접속 유예를 다시 줍니다.
- 2인전 점수: 1위 20 / 2위 0. 3인전 점수: 1위 30 / 2위 10 / 3위 0. 4인전: 1위 40 / 2위 20 / 3위 5 / 4위 0. 기권해도 확정된 순위 점수로 기록합니다. 경기 종료 저장은 트랜잭션과 고유 키로 중복 반영을 막습니다.
- SQLite 테이블: users, accounts, auth_sessions, account_recovery, rooms, matches, participants, augment_choices, single_records. 기존 테이블을 삭제하지 않고 새 테이블을 추가합니다. 전적·증강 선택은 영구 저장합니다. 방 스냅샷은 갱신하며 종료·비접속 방은 메모리에서 정리합니다.
- 누적·월별(UTC 월) 랭킹과 최근 개인 전적을 대기실에서 조회할 수 있습니다. 로그인하고 시작한 싱글 결과는 별도 `single_records`에 저장하며 온라인 점수에는 반영하지 않습니다. 싱글 결과는 브라우저가 보고하는 기록이며 서버가 검증한 경쟁 전적이 아닙니다.

기본 DB는 저장소의 `data/yutverse.sqlite`입니다. 서버 프로세스는 1개로 실행해야 합니다. 확장된 다중 서버/Redis 동기화는 지원하지 않습니다. SQLite 파일과 WAL/SHM을 실행 중 임의로 복사하기보다 SQLite 백업 API 등 일관된 백업 방법을 사용하세요.

### 환경 변수 / HTTP API

| 이름 | 기본값 / 설명 |
|---|---|
| PORT | 3001 |
| YUTVERSE_DATA_DIR | 기본 저장소 `data/`; 운영 시 쓰기 가능한 절대 경로 권장 |
| WEB_ORIGIN | 별도 프런트엔드 출처를 허용할 때 정확한 origin 지정. 기본은 같은 출처만 허용 |

- `POST /api/auth/register`: `{login,password,nickname}`. 기존 게스트 연결 시 Bearer 토큰을 함께 보냅니다.
- `POST /api/auth/login`: `{login,password}`. 가입/로그인 응답은 `{token,user:{id,name,login}}`이며 신규 가입에는 한 번만 표시하는 `recoveryCode`가 추가됩니다. 선택 옵션 `{remember:boolean}`으로 로그인 유지를 지정합니다.
- `GET /api/auth/me`, `POST /api/auth/logout`: Bearer 로그인 토큰. 참가 중인 방이 있으면 먼저 나가야 로그아웃할 수 있습니다.
- `GET /api/account/records`: 로그인한 계정의 온라인 최근 50건, 싱글 최근 100건, 온라인 누적 경기·승리·점수.
- `POST /api/account/single-record`: `{id,rank,turns,players,character,forfeited}`. 계정·경기 ID로 중복 저장을 막고 온라인 점수를 변경하지 않습니다.
- `GET /api/health`, `GET /api/ranking`, `GET /api/ranking?season=YYYY-MM`, `GET /api/history`. `/api/history`는 Bearer 토큰으로 본인 기록만 조회합니다. 기존 클라이언트 호환용 `POST /api/session`도 유지합니다.

Socket.IO 이벤트는 `rooms`, `create`, `join`, `character`, `ready`, `start`, `sync`, `act`, `leave`, `exit`입니다. `exit`는 진행 중이면 서버에서 기권 후 방을 나가며, 이미 완주한 사람은 확정 순위를 유지합니다. 나머지 사람들의 경기가 계속되면 그 경기의 최종 종료 시 전적을 확정합니다. 증강 선택 중에도 나가기가 가능합니다. 세션 토큰·아이디·비밀번호 해시는 공개 방 상태에 포함하지 않습니다. 로그인·가입·소켓 요청 빈도를 제한합니다.

## 구조와 검증 범위

- `packages/engine/src/index.ts`: 브라우저·서버 공통 규칙, 불변 상태 전이.
- `packages/engine/src/augments.ts`: 증강 26종과 후보/충돌 제약.
- `packages/engine/src/ai.ts`: 렌더링과 분리된 AI 선택 로직. 쉬움은 무작위, 보통은 완주/잡기, 어려움은 업기 가중치를 추가합니다.
- `apps/web`: 3D 윷판·간단한 SD 말, 카메라/터치 제어, 저사양 옵션, 싱글/온라인 UI. 진행 상태와 최근 싱글 기록 200건을 localStorage에 저장하고 계정 기록은 서버에서도 조회합니다.
- `apps/server`: Express, Socket.IO, SQLite 저장과 복구.

테스트는 확률 16조합, 기본 이동, 모든 증강 효과, 영웅/충돌/슬롯/횟수 제한, 선택 정지/타임아웃, AI 경기 완결, 실제 소켓 2·3·4인 경기 완주와 점수 저장, 불법 요청/재전송 거부, 재접속/기권, SQLite 재시작 복구를 검사합니다. Playwright 테스트는 세 브라우저의 대기실·준비·선택·던지기·새로고침 재접속·기권·종료를 실제 UI로 확인합니다. 브라우저에서 모든 자연 완주 경기를 돌리는 대신 소켓 통합 테스트로 전체 경기 완결을 확인합니다.

## 남은 작업

캐릭터 획득·상점, 입체 캐릭터 리깅, 증강 전용 3D 이펙트, 이메일/SMS 본인확인·외부 로그인, 고정 도메인 상시 운영은 미구현입니다. 기존 3D 시안은 제공되지 않아 대조하지 못했습니다. Three.js 번들 크기 경고가 남아 있습니다.

2015 MacBook Pro의 실제 macOS 버전과 해당 OS에서 지원되는 Node.js를 확인하기 전에는 운영 설치 환경을 확정하지 않습니다. 현재 서버는 Node 24의 `node:sqlite`를 요구하므로 구형 macOS의 공식 Node 지원 범위를 우선 확인해야 합니다. 클라우드 Linux에서의 검증은 Mac 호환성 검증이 아닙니다.

## 외부 공개 배포

임시 공개 배포 실행기를 추가했습니다: `npm run tunnel:install` → `npm run deploy:quick`.
현재 클라우드의 DNS/아웃바운드 정책 때문에 터널 발급은 차단되어 **공개 URL은 아직 없습니다**. 필요한 네트워크 설정, 검증 상태와 재개 절차는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.

Intel Mac / Monterey 사용자는 [MAC_SETUP.md](MAC_SETUP.md)를 참고하세요. `npm run tunnel:install:mac`은 Monterey 호환 Go 도구체인으로 공식 Cloudflare 소스를 빌드하며, 사용 중인 Node.js를 교체하지 않습니다. 사용자가 제공한 로그에서 Mac의 터널 등록 및 공개 웹/API/Socket.IO 초기 연결 성공을 확인했습니다. 이번 변경의 Mac 실기 검증은 별도입니다.

게임 화면은 브라우저 전체 크기로 표시하며, 상단 `전체화면`으로 지원 브라우저의 전체화면 모드에 진입할 수 있습니다. AI 난이도·저사양 모드·싱글 새 경기는 `설정`, 보유 카드는 `나의 증강`에서 엽니다. 큰 캐릭터·플레이어 색상·이름표·선택 테두리를 표시하고, 업은 말은 한 캐릭터와 `×N` 배지로 표시합니다. `npm run test:game-view`는 실행 중인 테스트 서버에서 PC/모바일 세로/가로 화면 크기, 말 표시, 직접 3D 말 선택, 전체화면 전환을 검사합니다 (`YUTVERSE_URL`, `CHROMIUM_PATH` 설정 가능).

Mac에서 터널을 유지하면서 화면만 업데이트하려면 실행 중인 터미널은 그대로 두고 **다른 터미널**의 저장소 폴더에서 `git pull --ff-only origin main`, `npm run build`를 실행한 뒤 브라우저를 새로고침하세요. 이 UI 변경에는 서버 재시작이 필요 없으므로 터널이 계속 실행 중이면 같은 주소를 사용할 수 있습니다.

## 이동·잡기 연출, 증강 선택 화면, 2인전

- 이동 시 실제 윷판 경로의 칸을 따라 뛰어 이동하고, 잡기가 확정되면 도착 지점의 링 효과와 함께 잡힌 무리가 회전하며 대기칸으로 돌아갑니다. 다시 출발/불사조 증강은 해당 복귀 칸으로 돌아갑니다. 완주는 마지막 구간을 지나 위로 사라지는 연출입니다.
- 이동 이벤트는 공통 엔진에서 생성하며 온라인에서는 서버가 확정합니다. 클라이언트의 연출은 규칙이나 난수를 바꾸지 않습니다. 애니메이션 중 화면의 중복 입력을 막고 싱글 AI의 다음 행동을 기다리게 합니다. 서버 시간 제한은 기존대로 유지합니다. 새로고침/재접속 시 지난 연출을 다시 재생하지 않습니다. OS의 동작 줄이기 설정을 존중합니다.
- 증강 선택 중에는 Canvas와 캐릭터를 렌더링하지 않고 불투명 전용 화면을 보여줍니다. 다른 게임 조작은 숨기고, 키보드 Tab 초점을 선택 카드 안에 유지합니다. 상대/AI의 선택을 기다릴 때도 이 화면을 유지합니다.
- 싱글 2인전: 설정 → 싱글 인원 2인 → 새 경기 시작. 온라인 2인전: 방 인원 2인 → 방 생성 → 한 명 참가 → 둘 다 준비 → 방장 시작. 첫 완주자 또는 기권으로 1·2위를 확정합니다.
- `npm run test:animation`: PC/모바일 잡기 동작·입력 잠금·재접속 시 중복 연출 방지·2인 싱글·맵 없는 선택 화면과 키보드 초점을 검사합니다. `YUTVERSE_PLAYERS=2 npm run test:browser`는 실제 두 브라우저의 온라인 방·준비·선택·재접속·기권을 검사합니다. `YUTVERSE_URL`로 테스트 서버를 지정합니다.

이번 변경은 서버의 2인전 규칙도 포함하므로 Mac에서는 기존 서버를 종료한 뒤 최신 코드를 받아 빌드하고 `npm run deploy:quick`을 다시 실행해야 합니다. 단순 화면 업데이트와 달리 빌드만 해서는 이미 실행 중인 서버에 새 규칙이 적용되지 않습니다.

## 규칙 보완과 윷 던지기 연출

이전 구현에서 첫 번째/두 번째 모서리의 대각선 통과 방향과 윷·모의 던지기/이동 순서를 보완했습니다. 자세한 기준과 지역별 차이가 있는 규칙은 [RULES.md](RULES.md)에 명시했습니다.

갈림길에 선 말을 선택하면 `어느 길로 갈까요?`에서 길을 고르고, 두 목적지를 다른 색 링으로 표시합니다. 중앙을 통과할 때는 대각선을 직진하며, 중앙에 정확히 멈췄다가 다음 결과로 움직일 때는 두 출구 중 선택합니다. 온라인 서버도 경로 선택을 검증합니다.

윷·모와 증강으로 받은 남은 던지기를 먼저 마치고, 모은 결과 버튼에서 이동 순서를 고릅니다. 윷 4개가 날아갔다가 떨어지는 연출을 사람과 AI 모두에게 표시합니다. 이동 직후 다음 증강 선택이 열리는 경우에도 이동을 끝까지 보여준 뒤 맵을 숨기고 선택 화면을 엽니다. 첫 3D 프레임을 준비한 뒤 연출 시간을 재므로 초기 화면 준비 때문에 모션이 생략되지 않게 했습니다. 이때 선택 제한 시간은 서버 시간을 따릅니다.

`npm run test:rules-browser`는 PC/모바일 경로 선택, 결과 보관 순서, AI 증강 선택 → 던지기 → 이동과 사람의 던지기 모션을 검사합니다. 테스트 서버 주소는 `YUTVERSE_URL`로 지정합니다. 이번 변경은 서버 규칙을 바꾸므로 업데이트·빌드 후 서버와 터널을 다시 시작해야 합니다.

## 캐릭터 말과 시작 전 선택

첨부된 캐릭터 그림을 바탕으로 준비한 투명 이미지 시트 세 장을 말과 선택 화면에 사용합니다. 선택 가능한 말은 13종이며 고른 캐릭터가 내 말 4개에 적용됩니다. 캐릭터에 따른 윷 확률·이동 거리·증강 차이는 없습니다.

- 처음 접속하거나 설정에서 새 경기를 시작하면 캐릭터·인원·AI 난이도를 고른 뒤 시작합니다. 새 경기 선택을 취소하면 진행 중이던 경기로 돌아갑니다.
- 싱글은 선택한 캐릭터와 경기 상태를 브라우저에 저장합니다. AI에는 다른 캐릭터를 배정합니다. 기존 저장 경기의 캐릭터 필드가 없으면 기사로 표시합니다.
- 온라인은 방 생성/참가 전과 대기실에서 선택할 수 있습니다. 변경하면 준비가 해제됩니다. 경기 시작 시 서버가 각자의 선택을 게임 상태에 고정하고 SQLite에 저장합니다. 진행 중 변경 요청은 거절하며 재접속 시 같은 선택을 복원합니다. 같은 캐릭터를 여러 사람이 골라도 발판 색과 번호로 구분합니다.
- 캐릭터는 **3D 윷판 위에서 카메라를 향하는 2D 스프라이트**입니다. 이동·업기·잡혀 돌아가기·완주 연출을 함께 적용합니다. 입체 모델의 뼈대/팔다리 걷기 애니메이션은 구현하지 않았습니다.
- `/characters/heroes.png`, `/characters/challengers.png`, `/characters/legends.png`는 앱과 함께 제공하는 로컬 이미지 시트입니다. 별도 이미지 서버나 외부 이미지 주소에 의존하지 않습니다.

`npm run test:characters-browser`는 PC·모바일 시작 화면, 4개 말 적용, 새로고침 유지, 새 경기 선택 취소를 검사합니다. 서버 테스트는 선택 동기화, 준비 해제, 진행 중 변경 차단과 SQLite 복구를 검사합니다. Mac에 반영하려면 최신 코드를 받은 뒤 빌드하고 서버·터널을 재시작하세요.

## 계정 전적과 게임 나가기

처음에는 로그인/회원가입 화면을 표시합니다. 서버 없이 싱글을 하려면 `로그인 없이 싱글플레이`를 선택합니다. 게임과 캐릭터 선택 화면의 `내 전적`에서 온라인/싱글 기록을 나눠 봅니다. 캐릭터 이름은 첨부 순서대로 바훈투르·니나브·샨디·실리안·샨디입니다.

로그인하고 시작한 싱글은 완료 또는 나가기 시 해당 계정에 저장합니다. 네트워크 오류 시 이 브라우저에 남겨 두고 같은 계정으로 다시 접속하거나 연결이 복구되면 재전송합니다. 미전송 기록을 다른 계정에 올리지 않습니다. 로그인 없이 시작한 경기는 로컬 기록이며 계정 랭킹에 합치지 않습니다. `게임 나가기`는 확인 후 기권으로 기록하며, 이미 완주한 상태에서는 기존 순위를 보존합니다. 게임 화면과 증강 선택 화면 모두에서 나갈 수 있습니다.

`npm run test:accounts-browser`는 PC 가입, 로그인/로그아웃, 증강 화면에서 나가기 취소/확정, 다른 기기에서 싱글 기록 조회, 온라인 나가기·점수 저장, 모바일 화면을 검사합니다. 서버 테스트는 비밀번호 해시·중복 아이디·인증 실패·세션 만료/폐기·요청 제한·게스트 계정 전환·계정별 기록 격리·중복 저장 방지·SQLite 재시작 복구도 확인합니다.

## 공개 방 목록과 비밀방

온라인 로그인 후 `참가할 방 찾기`에서 방을 눌러 입장합니다. 방장·제목·현재 인원·최대 인원·잠금 여부와 대기/정원 마감/게임 중 상태를 실시간 갱신합니다. 진행 중이거나 정원이 찬 방은 입장할 수 없고, 종료된 방은 목록에서 사라집니다.

방 만들기에서 제목(최대 32자), 2~4인, 비밀번호 사용 여부를 고릅니다. 비밀번호(최대 32자)는 서버에서 무작위 salt와 `scrypt` 해시로 보관하며 공개 목록·방 상태에는 원문이나 해시를 보내지 않습니다. 비밀방은 목록 클릭이나 초대 코드 입장 모두 서버의 비밀번호 확인을 거칩니다. 서버 재시작 후에도 제목·잠금 설정을 복구합니다. 비밀번호 확인 중 다른 입장이 진행돼도 정원을 넘지 않게 재검사합니다.

`npm run test:rooms-browser`는 PC·모바일 실시간 방 목록, 비밀방 오답/정답, 정원 마감·게임 중·종료 표시, 에키드나/아만 말 적용, 공개방 클릭 입장을 검사합니다. 단위/소켓 테스트는 방 비밀번호 해시 비공개, 재시작 복구와 동시 입장 경쟁도 검사합니다.

추가 캐릭터: 에키드나·카마인·쿠크세이튼·카멘·루테란·발탄·갈라투르·아만. 기존 5종과 합쳐 13종이며 성능 차이는 없습니다.

### 온라인 게임 화면의 방 정보

경기 중 방 제목과 초대 코드는 상단 조작부에 표시하지 않고 `설정 → 방 정보`에서 확인합니다. 대기실에서는 제목과 코드를 그대로 보여줍니다. 경기 종료 후 `대기실로 돌아가기`는 게임 조작 패널에 표시하며, 기권은 설정의 방 정보에서도 할 수 있습니다.

`npm run test:online-layout`는 실제 온라인 방에 32자 연속 영문 제목과 16자 닉네임을 적용한 뒤 PC·태블릿·휴대폰 세로/가로 16개 크기를 검사합니다. 상단 버튼·탭·시점 초기화·증강 버튼의 겹침, 화면 넘침, 윷 던지기 버튼을 가리는 요소와 설정 안의 방 정보 표시를 확인합니다.

세로 화면은 높이 500px 이하에서도 세로 배치를 유지합니다. 방향은 화면 너비/높이로 판단하며, 3D 카메라는 실제 하단 조작 패널 높이와 안전 영역을 측정해 윷판을 배치합니다. 세로 3~4인전의 플레이어 목록은 균등한 칸으로 표시하고, 말 위 이름표는 작은 화면에서 색상·말 번호를 우선 표시합니다.

`YUTVERSE_LAYOUT_PLAYERS=4 npm run test:online-layout`로 긴 닉네임의 4인전을 검사합니다. 320×480, 360×500 같은 짧은 세로 화면에서 상단 탭/조작부 및 말 이름표 겹침도 확인합니다. `YUTVERSE_LAYOUT_PLAYERS=3`은 3인전 검사입니다.

## 회원정보 찾기·로그인 유지·상대 증강

- 신규 가입 시 복구코드를 한 번 표시합니다. 복사하거나 파일로 내려받아 보관합니다. 서버에는 코드의 SHA-256 해시만 저장하고 원문은 브라우저 저장소에도 남기지 않습니다.
- 로그인 화면의 `회원정보 찾기`에서 복구코드로 아이디·닉네임을 확인하거나 비밀번호를 재설정합니다. 재설정은 기존 로그인 세션을 모두 폐기하고 복구코드를 교체합니다. 예전 코드는 다시 사용할 수 없습니다.
- 기존 계정은 먼저 로그인하고 캐릭터 선택 화면의 `회원정보` 또는 게임 설정의 `회원정보 · 복구코드`에서 현재 비밀번호를 확인한 뒤 코드를 발급합니다. 사전에 코드가 없고 비밀번호도 모르는 기존 계정의 자동 복구는 제공하지 않습니다. 닉네임만으로 계정을 변경하지 않습니다.
- 로그인 유지 여부를 선택할 수 있습니다. 브라우저 저장소는 주소별로 분리되므로 임시 Cloudflare 주소가 바뀌면 같은 계정으로 다시 로그인해야 합니다.
- 플레이어 목록의 이름을 누르면 해당 플레이어의 증강 종류·효과·남은 횟수·소모 여부를 읽기 전용으로 봅니다. 본인/상대/AI 모두 같은 화면으로 확인하며 선택 중 후보는 공개하지 않습니다.
- 모바일 턴 안내는 기본 설명과 추가 던지기 도움말을 서로 다른 격자 행에 배치합니다. 윷/모를 보관한 채 다시 던지는 상태에서도 문구가 겹치지 않습니다.

추가 API: `POST /api/auth/recover-id` (`{code}`), `POST /api/auth/reset-password` (`{code,password}`), `POST /api/auth/recovery-code` (Bearer 로그인 및 `{password}`로 코드 발급·재발급). 요청 횟수를 제한하며 복구코드 조회/재설정 응답은 캐시하지 않습니다.

검사: `npm run test:recovery-browser`는 가입 코드 표시, 아이디 찾기, 비밀번호 변경, 탭 세션/로그인 유지, 브라우저 저장 복원과 기존 계정 코드 발급을 확인합니다. `npm run test:turn-augments`는 첨부 스크린샷과 같은 남은 던지기/보관 결과 상태에서 모바일 안내 겹침과 상대 증강의 읽기 전용 표시를 확인합니다. 이번 변경은 서버 API와 DB 테이블을 추가하므로 빌드 후 서버·터널을 재시작해야 합니다.
